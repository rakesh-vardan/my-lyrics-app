4 What to keep in mind

✓ Writes are gated on the server

No anon key ships to the browser and there are no public write policies. POST/PATCH verify an HMAC-signed httpOnly cookie before touching the database, and every field is validated first.

◆ Search without a search extension

pgroonga isn't available on Neon, so search is ILIKE '%term%' over four columns, indexed with pg_trgm. Ranking still prefers title → movie → lyrics. Fast for hundreds to a few thousand songs.

◆ One fetch, cheap renders

The library query deliberately omits lyrics, so the whole index stays small. Full lyrics are fetched once, only on the song page. This works well up to a few thousand songs.

✓ No accounts, by design

Favorites and history live in the browser. The app is personal: one curator, many readers. That is also why the app can be static-ish and fast.

⚠ Favorites are duplicated

hooks/useFavorites.ts and components/FavoriteButton.tsx both own lyrics-vault-favorites with separate implementations, so a toggle on the detail page doesn't live-update the home list.

◆ Theme via palette inversion

Instead of dark: variants, html.light overrides Tailwind's slate color variables. Elegant and small — but non-slate colors (violet, pink) need manual attention.
